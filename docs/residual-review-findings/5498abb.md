## Findings

1. **[P2, testing]** No test exercises `JOB_SEARCH_LINKEDIN_ENABLED`/`JOB_SEARCH_XING_ENABLED` set to `false` — the source-exclusion branch in `backend/app/services/job_search_service.py` (`JobSearchService.search`) is unverified.
2. **[P2, testing]** LinkedIn's `reason="rate-limited"` status isn't exercised end-to-end through `JobSearchService` with the real `LinkedInJobsClient` — only `LinkedInJobsClient`'s own unit tests cover the cooldown; the orchestrator's `LinkedInJobsClient.is_cooldown_active()` check (`backend/app/services/job_search_service.py:424`) has no test from the `JobSearchService` side.
3. **[P1, testing]** `ArbeitsagenturJobsClient`'s v4→v6 response-parsing rewrite (bundled into this branch's history, pre-dating this feature) has zero dedicated test coverage — every other source client got fixture-based tests, this one didn't.
4. **[P2, maintainability]** `JobSearchService.search()`'s fan-out loop special-cases Arbeitsagentur (for the fallback trigger) and LinkedIn (for the rate-limited reason) via `source_name ==` string comparisons rather than a uniform per-client interface (`backend/app/services/job_search_service.py:416-425`). Suggested direction: give every client a uniform way to report why it came back empty, so the orchestrator loop stays source-agnostic.
5. **[P3, maintainability]** `primary_clients` is typed `dict[str, Any]` (`backend/app/services/job_search_service.py:381`), so the shared `.search()` contract across clients isn't type-checked. A small `Protocol` would catch a future signature drift at the call site instead of at runtime.
6. **[P2, security]** `GET /jobs/search` has no request-level throttling despite now launching a real headless-Chromium process (Xing) and making outbound scraping calls (LinkedIn) per call. Already an accepted, documented risk in the plan's Risks & Dependencies section — recorded here for tracking, not new.
7. **[P3, security, advisory]** Scraped LinkedIn/Xing job titles/company names flow unsanitized into the OpenAI prompt in `backend/app/services/ai_generator.py` (not touched by this diff) that generates cover-letter content — a prompt-injection surface that's wider now that these sources are automatic rather than a manually-pasted URL. Already surfaced during planning (`ce-doc-review` security-lens pass) and left as a known follow-up.
8. **[P3, correctness, pre-existing]** `frontend/src/app/pages/job-search/job-search.component.ts`'s `onSearch()` has no stale-request cancellation (no `switchMap`/request-id guard) — a fast second search can have its response overwritten by a slower first search's late-arriving response. Pre-existing behavior, not introduced by this diff, but the new multi-source fan-out's higher latency variance makes it more likely to actually manifest in practice.
